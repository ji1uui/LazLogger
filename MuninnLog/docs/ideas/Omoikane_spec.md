# Omoikane アプリケーション実装仕様書（統合版）

## 1. アプリケーション概要

### 1.1 目的

「Omoikane」は、アマチュア無線コンテストに参加するオペレータを対象とした、クロスプラットフォーム対応のログ管理・規約適用・得点計算システムです。動的なプラグインシステム「Yata Logic (.ylg)」により、国内外の多様なコンテスト規約に柔軟に対応します。

### 1.2 対象プラットフォーム & 開発環境

* **サポートOS:** Windows 10以降 / macOS 11以降 / Ubuntu 20.04以降
* **言語 / フレームワーク:** Lazarus IDE / Free Pascal Compiler (FPC 3.2.2以上)
* **ビルドツール:** Makefile / バッチファイルによるクロスプラットフォームビルド対応、GitHub Actions による CI/CD マトリクスビルド

## 2. システム構造・アーキテクチャ

### 2.1 開発時（ビルド）アーキテクチャ

開発マシン上の Lazarus IDE およびソース管理構成です。

```
[開発マシン]
   ├─ Lazarus IDE / FPC (Free Pascal)
   ├─ core/*.pas (ビジネスロジック)
   ├─ utils/*.pas (共通ヘルパー)
   ├─ plugins/*.ylg (プラグインテンプレート)
   └─ build_windows.bat / Makefile.macos / Makefile.linux
         │
         ▼
   Omoikane.exe (各OS向けバイナリ生成)

```

### 2.2 利用時（ランタイム）アーキテクチャ

ユーザーの実行環境におけるコンポーネント構造とデータフローです。

```
[ユーザー / CLI]
   │ (起動リクエスト / 引数入力)
   ▼
[Omoikane.exe (Main Executable)]
   ├─ config.ini (設定読込・永続化)
   ├─ plugins/*.ylg (プラグインスキャン＆動的ロード)
   ├─ UI Layer (forms/) ── Observerパターン ──► TDataManager (Subject)
   ├─ Core Logic (core/)  ◄────────────────────── TCoreLogicManager (Action Executor)
   ├─ Import / Export モジュール (ADIF, CSV, Cabrillo変換)
   └─ Undo/Redo マネージャ (IUndoableAction)

```

## 3. 機能要件

### 3.1 ログ管理機能

* **インポート / エクスポート:** ADIF, CSV, Cabrillo, JSON 形式の相互変換。
* **ログエディタ (グリッドUI):**
* スプレッドシート形式による QSO データの直接編集。
* **リアルタイムエラー検出:** 必須フィールド（コールサイン、RST、交換情報など）の欠落やフォーマット違反のセルを赤枠でハイライトし、マウスオーバーでツールチップによるエラー理由を表示。
* **Undo/Redo:** すべてのデータ変更操作における履歴管理（`TUndoManager` による安全な状態復元）。



### 3.2 規約適用 & 得点計算（Yata Logic）

* **プラグインシステム (.ylg):**
* `.ylg` ファイルは ZIP アーカイブとしてパッケージングされる。
* `rules.json`: コンテスト名、バンド、カテゴリ、交換情報、得点・マルチプライヤー定義。
* `score_calculator.omk`: Pascalスクリプトによる得点ロジックの記述。
* `export_format.omk`: Pascalスクリプトによるカスタム出力フォーマット定義。




* **プラグインマネージャ:**
* 動的なプラグインの追加・削除・有効化/無効化。
* プラグイン詳細（ルールJSONの抜粋）のプレビュー表示。



### 3.3 コマンドライン（CLI）機能

GUIを起動せず、バックグラウンドでのバッチ処理や自動化に対応する引数仕様：

| 引数 | 説明 | 戻り値コード |
| --- | --- | --- |
| `--help` | 使用可能な引数一覧表示 | `0` |
| `--load <file>` | 指定ログファイルのロード | `0` (成功) / `1` (ファイル未検出・失敗) |
| `--export <format>` | 指定形式でのエクスポート | `0` (成功) / `2` (未対応フォーマット) |
| `--plugin <file>` | プラグインの明示的ロード | `0` (成功) / `3` (署名検証NG) |
| `--quiet` | GUIなしバッチモード（非対話） | `0` (成功) / `4` (入力パラメータ不正) |
| `--version` | バージョン情報表示 | `0` |

## 4. UI/UX 設計と画面遷移

### 4.1 画面構成要素

1. **メインダッシュボード**
* ヘッダー（グローバルメニュー、ファイル、設定、ヘルプ）
* 左パネル（ロード済みプラグイン一覧、有効/無効トグル）
* 右上エリア（リアルタイム得点集計カード、コンテスト種別・獲得マルチ・合計得点）
* 中央・下部エリア（アクションボタン：ログ編集、プレビュー、得点再計算、ステータスバー）


2. **プラグインマネージャ**
* プラグインテーブル（名前、バージョン、ステータス）
* 操作アイコン（有効化/無効化、設定、削除）
* 検索ボックス、カテゴリフィルタ、選択中プラグインのルールプレビュー


3. **ログエディタ**
* QSOデータグリッド（スプレッドシート形式）
* リアルタイム検証（赤枠・ツールチップ）
* ツールバー（一括保存、エラー一覧、Undo/Redo）


4. **フォーマットプレビュー**
* 左側：エクスポート形式タブ（Cabrillo / JARL / JSON / 独自）
* 右側：リアルタイム出力テキストプレビュー
* 下部：ファイル保存、クリップボードコピー、戻るボタン



### 4.2 画面遷移フロー

すべてのサブ画面は、原則として**メインダッシュボード**をハブとして双方向に遷移します。操作ステップは最大3クリック以内に設計します。

```
メインダッシュボード
  ├─► プラグインマネージャ ──(「戻る」/「タブ選択」)──► メインダッシュボード
  ├─► ログエディタ ────────(「保存して戻る」)────────► メインダッシュボード
  ├─► フォーマットプレビュー ──(「閉じる」)─────────► メインダッシュボード
  └─► 設定画面 ────────────(「保存して閉じる」)──────► メインダッシュボード

```

## 5. 非機能要件

### 5.1 セキュリティ

* **プラグイン安全性担保:** `.ylg` ファイル読み込み時に SHA-256 ハッシュチェックおよびデジタル署名の検証を実施。署名不正のプラグインはロードを拒否しエラーコードを返却。

### 5.2 アクセシビリティ & ユーザビリティ

* **キーボードショートカット:** `Ctrl+L`（ログ読込）、`Ctrl+E`（エクスポート）、`Tab`キーによる全項目フォーカス遷移、`F1`キー（ヘルプ呼出）。
* **スクリーンリーダー対応:** 主要なUI要素への適切な ARIA 属性の付与、高コントラストテーマ選択機能。
* **操作性:** ログ・設定変更の常時 Undo/Redo 対応。

### 5.3 テスト計画 & 品質保証

* **単体テスト:** カバレッジ 80% 以上を目標とする。
* **結合テスト:** プラグインロード機構および異常系（署名NG、ファイル破損）の網羅的テスト。
* **静的解析:** PascalLint によるコード規約チェックの定期実行。
