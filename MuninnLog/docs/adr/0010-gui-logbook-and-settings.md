# 0010: GUI 版のログブックの扱いと設定の保存場所

- 状態：提案（この ADR を含む PR のマージで決定）
- 日付：2026-10-23
- 関連：M1 タスク T12（[05_DEVELOPMENT_PROCESS.md](../05_DEVELOPMENT_PROCESS.md) 第 13.2 節）、[ADR 0003](0003-storage-sqlite.md)、[ADR 0009](0009-ui-technology.md)

## 背景

T10 の試作は、デモデータだけで動いていた。M1 の GUI 版では、次の 3 点を決める必要がある。

- 利用者のログブック（SQLite のファイル、ADR 0003）を開く・作る・閉じる方法
- 設定をどこに保存するか
- 「最近使ったログブック」をどう扱うか

## 選択肢

### ログブックの持ち方

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **利用者が選んだファイルを 1 つ開く（ワープロと同じ）** | 置き場所を利用者が決められる（クラウドの同期フォルダーなど）。複数のログブックを使い分けられる | ファイルを選ぶ手間がある |
| アプリの決まった場所に 1 つだけ置く | 迷わない | 置き場所を変えられない。運用ごとに分けられない |

### 設定の保存場所

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **OS の慣習に従う** | 利用者や他のツール（バックアップ）が見つけやすい | OS ごとに分岐する |
| 実行ファイルの隣 | 持ち運べる | macOS の `.app` や Program Files では書き込めない |

## 決定

1. **ログブック**
   - 利用者が選んだファイルを 1 つ開く。
   - 「新しいログブック」は既存のファイルを上書きしない。
   - 「開く」は存在しないファイルを作らない。
   - 「開く」は、ファイルがログブックであること（スキーマの版が 1 以上で `qso` テーブルがある）を読み取りだけで確かめてから、WAL の設定とマイグレーションを行う。空のファイル、ほかのアプリの SQLite のファイル、作成の途中で止まったログブックは、変更せずに断る。
   - 拡張子は `.muninnlog` を標準とする。中身は SQLite のファイル（ADR 0003）で、`.sqlite` などほかの名前のファイルも開ける。
2. **中核のポート**：`ILogbookStore`（`Open`、`CreateNew`）と `ILogbook`（`Muninn.Core.Logbook`）。
   - SQLite の実装は `Muninn.Storage.Logbook`。
   - 失敗は `ELogbookError` で、次の種類を区別する：見つからない、既にある、新しい版で書かれた（変更しない）、ログブックではない・壊れている、他のプログラムが使用中、その他。
3. **画面の判断**：`TLogbookPresenter`（`Muninn.UI.Logbook`、LCL に依存しない）が受け持つ。
   - 開くのに失敗したときは、開いていたログブックをそのまま残す。
   - 起動時は、最近使ったログブックのうち最新のものを開く。
4. **最近使ったログブック**
   - 最大 8 件。開くたびに先頭へ移す。
   - 見つからなくなったファイルは一覧から外す。
5. **設定の保存場所**（`Muninn.Storage.Settings`）

   | OS | 場所 |
   |---|---|
   | Windows | `%APPDATA%\MuninnLog` |
   | macOS | `~/Library/Application Support/MuninnLog` |
   | Linux | `$XDG_CONFIG_HOME/muninnlog`（未設定なら `~/.config/muninnlog`） |

   - 環境変数 `MUNINN_CONFIG_DIR` で置き換えられる（テスト、持ち運び用）。
   - 一覧のファイルは、一時ファイルに書いてから 1 回の操作で置き換える（Windows は `MoveFileEx`、Unix は `rename`）。保存の途中で強制終了しても、前の一覧か新しい一覧のどちらかが残る。
6. **T10 の試作のデモ**：`muninn-gui --demo` に分ける。反応速度の測定（`--measure`）はデモでだけ行う。
7. **ファイル名の文字コード**：`Muninn.Core.Utf8Default` で、OS に渡すファイル名の文字コードも UTF-8 にする。
   - Unix では、これまでロケールから決まっていた。そのため C ロケールでは、日本語の名前のファイルを `FileExists` が見つけられなかった（SQLite は UTF-8 の名前で作っていた）。

## 結果

- GUI 版の利用者のデータは、選んだログブックのファイルと、設定ディレクトリの一覧だけになる。
- 入力した QSO はまだログブックに保存しない。T13 で保存する。
- 次はまだ無い。
  - ログブックの中の QSO の表示（T14）
  - 周波数の手入力（T13 または T16）

**見直す条件：**

- 設定の項目が増え、1 つのファイル（JSON など）にまとめる必要が出たとき
- 複数のログブックを同時に開く必要が出たとき
