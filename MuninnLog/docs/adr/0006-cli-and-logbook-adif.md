# 0006: muninn-cli のコマンド・終了コードと、ログブックへの ADIF の保存

- 状態：提案（この ADR を含む PR のマージで決定）
- 日付：2026-10-18
- 関連：M0 タスク T7（[05_DEVELOPMENT_PROCESS.md](../05_DEVELOPMENT_PROCESS.md) 第 13 節）、[00_DEVELOPMENT_POLICY.md](../00_DEVELOPMENT_POLICY.md) 決定事項 D18、[ADR 0003](0003-storage-sqlite.md)、[ADR 0004](0004-adif-import-export.md)

## 背景

M0 の完了条件は、ADIF を読み込んで SQLite に保存し、ADIF に書き戻せること。
これを `muninn-cli` で行う（05 第 13 節）。

終了コードは Omoikane 仕様書（[ideas/Omoikane_spec.md](../ideas/Omoikane_spec.md) 3.3 節）の表を基本とする。
ただし、その表には次の失敗を表すコードが無い。

- 一部のレコードを取り込めなかった
- ログブックを開けない

保存についても決めることがある。ADR 0004 は、メモリ上の変換で値を失わないことを決めた。DB を経由しても同じ値が戻る必要がある。

## 決定

### コマンド

| コマンド | 内容 |
|---|---|
| `muninn-cli import --db <ログブック> <ファイル.adi>` | ADIF を取り込む。ログブックが無ければ作る。結果の要約を標準出力に、警告とエラーを標準エラー出力に書く |
| `muninn-cli export --db <ログブック> [--format adif] [--output <ファイル>]` | ログブックの全 QSO を ADIF で書き出す。`--output` が無ければ標準出力に書く。標準出力にはバイト列をそのまま書く（コンソールの文字コード変換をしない） |
| `muninn-cli --version` / `--help` | 版を表示する／使い方を表示する |

### 終了コード

| コード | 意味 | Omoikane 仕様書との関係 |
|---|---|---|
| 0 | 成功（警告があっても成功） | 同じ |
| 1 | ファイルの失敗（入力ファイルやログブックが無い、読み書きできない） | 同じ |
| 2 | 未対応の形式（`--format`） | 同じ |
| 3 | 予約（規約パッケージの署名の検証に失敗。Omoikane で使う） | 同じ |
| 4 | 引数の誤り | 同じ |
| 5 | データの誤り。QSO にできないレコードがあった。取り込めたレコードは保存する | 追加 |
| 6 | ログブックの誤り（SQLite が無い、アプリより新しい版のログブック、保存の失敗） | 追加 |

### 取り込みの単位

- 1 回の取り込みを 1 つのトランザクションで行う。
- 保存に失敗したら、そのファイルの QSO を 1 件も保存しない。
- QSO にできないレコードは飛ばし、終了コード 5 で知らせる。
- 同じファイルを 2 回取り込むと、QSO も 2 回保存される。重複の検出は後のタスクで扱う。

### ログブックへの保存（スキーマ v3）

1. 型付きの値（日時、周波数、バンド、モード、出力）は、その列に保存する。
2. ADIF のフィールドのうち、同じ名前の列があるもの（`NAME`、`STATE`、`CNTY`、`DXCC` など）は、その列に保存する。ただし、次の場合は列に入れず、`qso_field` に保存する。
   - データ型の指示子が付いている
   - INTEGER の列で、値が正規の整数表記ではない（`001`、`0339`、`+5` など）。書かれたとおりの文字列を残すため。
3. それ以外のフィールドは、`qso_field` に保存する。保存するもの：名前、値、データ型の指示子、記録された順序（`position`）
4. ADIF ヘッダーの `USERDEFn`（ユーザー定義フィールドの定義）は、`adif_user_field` に保存する。書き出しのとき、ヘッダーに `USERDEF1`〜 として書く。同じ名前で別の定義が来たら、先の定義を残して警告を出す。
5. `station_callsign` は NOT NULL の列とし、記録が無ければ空文字列を入れる。空文字列は書き出さない。

### 往復の確認

- 書き出しの順序は、型付きの項目、列のある項目（固定の順序）、`qso_field` の項目（記録順）とする。そのため、ADR 0004 のメモリ上の変換とはフィールドの順序が異なる。
- フィールドと値の組はメモリ上の変換と一致させ、テストで確かめる。
- ゴールデンテストは `tests/golden/adif/<名前>.cli-expected.adi`。

## 結果

- CI で、実際に `muninn-cli` を別プロセスとして起動して試験する。
  - 取り込み → 書き出し → 別のログブックへの再取り込み → 再書き出しが、一致すること
  - 終了コード（0・1・2・4・5・6）
- `scripts/test.sh` は、結合テストの前に `muninn-cli` をビルドする。

**見直す条件：**

- Cabrillo や JARL 電子ログなど、ほかの形式を加えるとき（`--format` の値を増やす）
- 重複の検出や、取り込みのやり直し（取り込み単位の取り消し）が必要になったとき
