# 0011: 入力した QSO の保存（保存スレッドと保存済みの表示）

- 状態：提案（この ADR を含む PR のマージで決定）
- 日付：2026-10-23
- 関連：M1 タスク T13（[05_DEVELOPMENT_PROCESS.md](../05_DEVELOPMENT_PROCESS.md) 第 13.2 節）、[04_ARCHITECTURE.md](../04_ARCHITECTURE.md) 第 7 節、[ADR 0003](0003-storage-sqlite.md)、[ADR 0010](0010-gui-logbook-and-settings.md)

## 背景

入力画面で Enter を押した QSO を、ログブック（SQLite）に保存する。両立させたい条件は 2 つある。

- 画面を待たせない。保存は保存スレッドで行う（04 第 7 節）。
- QSO を失わない（00 第 3 節）。

ただし、保存スレッドに渡してからディスクへの書き込み（fsync）が終わるまでの間（通常は数 ms）に強制終了すると、その QSO は失われる。Enter の中で書き込みまで終えれば失わないが、遅いディスク（HDD、ネットワークドライブ、同期フォルダー）では入力が止まる。

## 選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **保存スレッドで保存し、保存済みかを表示する** | ディスクが遅くても入力が止まらない | 保存の完了前の数 ms に強制終了すると、その QSO は失われる。利用者には「保存中」と見えている |
| Enter の中で書き込みまで終える | Enter が終わった QSO は必ず残る | ディスクが遅いと画面が止まる |

## 決定

開発者の判断（2026-10-23）で、保存スレッドで保存し、保存済みかを表示する方式とする。

1. **ポート**：`IQsoWriter`（`Muninn.Core.QsoWriter`）。
   - `Submit` は QSO をキューに入れ、すぐに番号（チケット）を返す。
   - 結果（保存済み / 失敗）は、メインスレッドに `TThread.Queue` で届く。LCL を使わないプログラムは `CheckSynchronize` を呼ぶ。
   - 結果は Submit の順に届く。
2. **SQLite の実装**：`TSqliteQsoWriter`（`Muninn.Storage.QsoWriter`）。
   - ワーカースレッド 1 本が、専用の接続で 1 件ずつ 1 トランザクションで保存する。
   - 接続の設定は `synchronous = FULL`（ADR 0003）なので、「保存済み」と通知した QSO は強制終了しても残る。
   - 保存に失敗した QSO はキューの先頭に残し、2 秒ごとに再試行する。後の QSO を追い越して保存しない。
   - 失敗の通知は、同じ QSO・同じエラーにつき 1 回にする。
   - キューの上限は 1000 件とする（04 第 7 節：キューはすべて上限付き）。満杯なら `EQsoQueueFull` を出し、入力欄を消さずに理由を示す。
   - `qso.source` は `'entry'` とする（ADIF の取り込みは `'adif'`）。
3. **画面の表示**
   - 記録の一覧の各行に状態を文字で示す：`[saving]`、`[saved]`、`[NOT SAVED - retrying]`、デモでは `[demo]`。
   - 状態表示には、保存待ちの件数、最後に保存した時刻（UTC）、失敗のときはその理由を出す（02 第 5 節の原則 5）。
4. **閉じるとき**
   - ログブックを閉じる・切り替えるときと、アプリを終了するときは、保存待ちを最大 5 秒待つ。
   - 終了するときにまだ残っていれば、終了してよいかを尋ねる。
   - ログブックを閉じたときに残っていれば、その件数を警告する。
5. **重複とパーシャルチェック**：ログブックを開いたときに、全 QSO のコール・バンド・モードを読み込んで使う（`ILogbook.LoadWorked`）。
   - バンドが記録されていない QSO は、周波数からバンドを求める。
   - 10 万件で、読み込みは約 0.4 秒、1 文字ごとの処理の p95 は 4 ms だった（手元の Linux）。
   - 一覧の並べ替えと検索は、ロケールに依存しないバイト順で行う。ロケールの照合順だと、10 万件の読み込みに 5 秒以上かかった。
6. **周波数の手入力**：入力欄に kHz の欄を設ける（例：`7010.5`）。無線機の連動（T16）が無くても記録できるようにする。

## 結果

- 保存の失敗（ディスクが満杯、ファイルのロックなど）で入力は止まらない。失敗は画面に残り、原因が取り除かれると自動で保存される。
- 「保存済み」と表示した QSO は失われない。「保存中」の QSO は、その間に強制終了すると失われることがある。
- `muninn-crash-helper writer` で、「保存済み」と通知した QSO が強制終了の後も残ることを試験する。

**見直す条件：**

- 実際の運用で、保存中の QSO を失う事例が出たとき（ジャーナルを別に持つなどを検討する）
- 複数のウィンドウやプロセスから同じログブックに書く必要が出たとき
