# 新ロギングアプリ 設計資料

Windows / macOS で動作する、新しいアマチュア無線ロギングアプリの検討成果をまとめるディレクトリです。
zLog の移植ではなく、zLog・CQRLOG ほか著名なロギングアプリを参考にした **新規アプリ** として構築します。

既存の `Lazarus/`（zLog Lazarus Edition の試作）と `zlog/` 等の Delphi 版には変更を加えません。
ここにある文書は提案段階であり、「決定事項」と明記したもの以外は確定していません。

## 決定事項

| # | 内容 |
|---|---|
| D1 | zLog の移植ではなく、新しいアプリとして構築する |
| D2 | 対象 OS は Windows と macOS |
| D3 | 無線機制御は、自分たちで開発している Hamlib コンポーネントを利用する |
| D4 | JA コンテスター全般を利用者として想定し、モダンなデザインで CTESTWIN / Turbo Hamlog など旧来アプリと差別化する |
| D5 | 国内外のコンテスト、FT8・RTTY・CW など多様なモード、POTA / SOTA 運用に対応する |
| D6 | 一人のオペレータが複数のコールサインを保持するケースに対応する |
| D7 | データモデルに Station Facility（設備）を導入する |

## 未決事項

| # | 問い | 影響 |
|---|---|---|
| Q1 | 最初に獲得する利用者は日常運用・FT8 ユーザーか、コンテスターか | リリース順（R1 と R3 のどちらを先にするか） |
| Q2 | 画面の技術は LCL＋独自描画か、WebView か | デザインの自由度、入力の反応速度、開発コスト |
| Q3 | 保存方式を SQLite（WAL モード）にするか | 検索・集計性能、移行方式 |
| Q4 | Hamlib コンポーネントの提供形態（ライブラリ / 別プロセス / Pascal ユニット） | 無線機ポートの設計 |
| Q5 | 実装を置く場所（`Lazarus/` を作り直すか、新ディレクトリにするか） | リポジトリ構成 |
